# PHOTO-PERSON-05 — UX для фото с человеком или несколькими вещами

Статус спецификации: **PASS**  
Статус пользовательского допуска ветки: **HOLD**  
Дата: 2026-08-21  
Scope: mobile-first UX и accessible copy; без изменения production runtime.

## 1. Решение

Текущий single-garment gate остаётся обязательным и fail-closed: автоматически или вручную принять можно только кадр с одной отдельной вещью, где отсутствие человека безопасно установлено в рамках действующего контракта. Фото с человеком, рукой, несколькими вещами, комплектом или неопределённой сценой не должно переходить в `accept`, `save_and_review`, upload, распознавание или карточку гардероба.

Вместо тупикового отказа UI объясняет ограничение без оценки пользователя и предлагает три безопасных действия:

1. **Кадрировать фото** — только если пользователь может оставить в кадре одну вещь и полностью исключить человека и остальные вещи.
2. **Переснять одну вещь** — предпочтительный и самый понятный путь.
3. **Выделить вещь вручную** — локально обозначить предмет для подготовки кадра; затем всё равно повторно проверить сцену. Контур сам по себе не снимает блок.

Это UX-ветка восстановления, а не поддержка person-scene recognition. Она не определяет, кто изображён, и не выполняет идентификацию личности.

## 2. Почему текущий default блокирует

Действующий контракт различает безопасный предметный кадр и всё остальное:

- `declareGarmentOnly(true)` означает только заявление «одна отдельная вещь без человека» и даёт максимум `save_and_review`, не `accept`;
- человек, неизвестное содержимое, неподдерживаемый объект и несколько вещей дают `retake`;
- ручной контур `manual-outline-v1` имеет provenance `user_confirmed`, но является лишь локальной подсказкой выбора области;
- автоматический допуск выключен, пока нет доверенного локального детектора;
- `upload_allowed` остаётся `false`, а отдельное согласие на processing не превращает заблокированную сцену в разрешённую.

Причина блока должна звучать как ограничение продукта, а не ошибка человека: системе нельзя честно выбрать ровно одну вещь и гарантировать, что в обработку не попадёт изображение человека или соседние предметы. Основанием служит только присутствие человека в кадре (`person_present`) либо невозможность безопасно исключить его (`person_unknown`). Никакая личность, сходство или идентификатор человека не устанавливаются.

## 3. Термины и запрещённые выводы

| Понятие | Разрешённое значение | Нельзя заявлять или хранить |
|---|---|---|
| `person_present` | В кадре виден человек или часть человека по декларации пользователя либо доверенному локальному сигналу | Кто это, совпадает ли человек с другим фото, имя или identity ID |
| `person_unknown` | Отсутствие человека не удалось безопасно подтвердить | «Человека нет» или любое предположение о личности |
| `multiple_garments` | Пользователь указал несколько вещей либо одну вещь нельзя однозначно изолировать | Автоматически выбранная «главная» вещь без подтверждения |
| `manual_outline` | Пользователь локально обозначил область одной вещи | Распознавание тела, сегментация человека, биометрический шаблон |

Запрещены face identity, face matching, embeddings/templates, body/health/age/gender/ethnicity inference и любые формулировки о внешности, теле или здоровье. Не использовать слова «ваше тело», «вы на фото», «лишние предметы», «неправильное фото» и «плохой кадр».

## 4. State machine

```text
selected_local
  -> scene_check
     -> single_garment_person_absent -> existing quality gate
     -> person_present | person_unknown | multiple_garments | ambiguous
        -> blocked_scene (no network, no save/review)
           -> crop_local -> scene_recheck
           -> retake -> selected_local
           -> manual_outline_local -> crop_preview -> scene_recheck
           -> cancel_delete -> empty
```

Инварианты:

- `blocked_scene`, crop и outline всегда имеют `network_allowed=false` и `upload_allowed=false`;
- crop создаёт новую локальную рабочую копию, не изменяет исходник и не дорисовывает пиксели;
- после crop/outline обязательна повторная декларация «одна вещь, человека в кадре нет» и действующий quality gate;
- если человек, рука, несколько вещей или неопределённость остаются, ветка снова блокируется;
- отмена удаляет preview, crop и outline текущей попытки из памяти; долговременное локальное хранение возможно только через отдельный действующий consent;
- demo assets и personal photo/drafts не смешиваются. Эта ветка относится только к явно начатой personal-попытке; demo-режим не получает пользовательское фото.

## 5. Mobile states и copy

Основная ширина проектирования — 320–430 CSS px; CTA идут вертикально, главный CTA первым. Каждая цель не меньше 44×44 CSS px. Нижняя панель учитывает safe-area и экранную клавиатуру, но не скрывает причину блока или delete.

### P0 — проверка сцены

**Заголовок:** «Проверим, что в кадре одна вещь»  
**Текст:** «Фото остаётся на этом устройстве. Ответьте про содержимое кадра — мы не определяем, кто на фото.»  
**Поля:**

- «В кадре виден человек или часть человека?» — «Нет» / «Да или не уверен(а)»;
- «Сколько вещей нужно добавить?» — «Одна» / «Несколько или не уверен(а)».

Нельзя предвыбирать безопасные ответы. Кнопка «Продолжить проверку» доступна только после ответа на оба вопроса.

### P1 — человек присутствует или не исключён

Роль: `alert`, фокус после submit переводится на заголовок ошибки.

**Заголовок:** «Нужен кадр только с вещью»  
**Текст:** «Сейчас приложение принимает одну отдельную вещь без человека в кадре. Это ограничение проверки фото — с вами и с фотографией всё в порядке.»  
**Privacy note:** «Мы проверяем только присутствие человека в кадре и не устанавливаем личность.»

CTA:

1. «Переснять одну вещь»;
2. «Кадрировать на устройстве»;
3. «Выделить вещь вручную»;
4. «Удалить фото».

Если safe crop невозможен: «Вещь соприкасается с человеком или не помещается целиком. Лучше переснять её отдельно.» Кнопка crop остаётся скрытой или disabled с программно доступным объяснением; retake остаётся доступен.

### P2 — несколько вещей

Роль: `alert`.

**Заголовок:** «Выберите одну вещь»  
**Текст:** «Одна карточка гардероба создаётся из одной вещи. Можно оставить одну вещь в кадре или переснять её отдельно.»  
**Подсказка:** «Другие вещи не будут добавлены автоматически.»

CTA: «Кадрировать одну вещь», «Переснять», «Выделить вручную», «Удалить фото».

### P3 — локальный crop

**Заголовок:** «Оставьте в кадре одну вещь»  
**Инструкция:** «Рамка должна включать вещь целиком и не включать человека, руки и другие вещи.»  
**Статус:** «Кадрирование выполняется только на этом устройстве.»

Действия: «Применить кадрирование», «Сбросить», «Назад», «Удалить фото». После применения: «Кадр подготовлен. Ещё раз подтвердите содержимое.» Нельзя показывать «Человек удалён»: crop лишь исключает область из новой копии.

### P4 — ручной контур

**Заголовок:** «Обведите одну вещь»  
**Текст:** «Контур помогает подготовить кадр локально. Он не распознаёт человека, тип, цвет или свойства вещи и не подтверждает безопасность фото.»  
**Инструкция:** «Поставьте не меньше трёх точек вокруг вещи. Не включайте человека, руки и соседние вещи.»

Действия: «Отменить точку», «Начать заново», «Подтвердить контур», «Назад», «Удалить фото». После подтверждения создаётся только локальный crop preview по границам контура с безопасным полем; пиксели внутри не изменяются, фон не генерируется, inpainting запрещён.

Для клавиатуры сохраняется альтернативный ввод X/Y в процентах. Для screen reader одной координатной формы недостаточно для самостоятельного понимания изображения, поэтому рядом всегда доступен равноправный путь «Переснять одну вещь»; UI не заявляет полную доступность визуального outlining без подтверждённого assistive workflow.

### P5 — повторная проверка

**Заголовок:** «Проверьте новый кадр»  
**Вопросы:** «В кадре одна вещь целиком?» и «Человека или части человека в кадре нет?»  
Ответы: «Да» / «Нет или не уверен(а)» без безопасного default.

Только два явных «Да» возвращают кадр в существующий quality gate. Это не `accept`: при текущем отсутствии trusted detector результат остаётся максимум `save_and_review`. Любая неопределённость возвращает P1/P2 с подсказкой переснять.

### P6 — удаление и отмена

**Заголовок диалога:** «Удалить выбранное фото?»  
**Текст:** «Исходник, кадрированная копия и ручной контур этой попытки будут удалены с устройства. Это действие нельзя отменить.»  
Кнопки: «Оставить фото» и «Удалить фото». После успеха `status`: «Фото и подготовленные копии удалены с устройства.» Если система не может доказать удаление долговременной копии: «Фото скрыто, но полное удаление пока не подтверждено»; не показывать ложный receipt.

### P7 — локальная ошибка

**Заголовок:** «Не удалось подготовить кадр»  
**Текст:** «Фото никуда не отправлено. Можно повторить локальную обработку, переснять вещь или удалить фото.»  
CTA: «Повторить», «Переснять», «Удалить фото». В telemetry допустим только coarse error code без фото, контура, координат и свободного текста.

## 6. Accessible interaction contract

- Один `h1` экрана; причина блока связана с действиями через `aria-describedby`.
- Новый блок объявляется один раз: `alert` для блокирующего результата, `status` для применения crop, подтверждения контура и удаления. Не перечитывать весь экран.
- Preview имеет нейтральное имя: «Выбранное фото для подготовки вещи»; alt не описывает человека и не делает выводов о теле.
- Crop handles и точки контура имеют видимый focus, понятные labels и текущее значение; операции доступны без drag. Масштабирование не должно требовать pinch.
- Порядок фокуса: причина → privacy note → основной CTA → альтернативы → удалить. После Back фокус возвращается на инициировавшую кнопку; после удаления — на input выбора фото.
- При 200% zoom, text spacing и 320 px нет горизонтального scroll, clipping или перекрытия CTA клавиатурой.
- `prefers-reduced-motion` отключает animated crop transitions и auto-pan; ни один статус не зависит от движения или цвета.
- Copy допускает перенос строк и увеличение до 2×; privacy note, причина, retake и delete не сворачиваются.
- Disabled control всегда имеет доступное объяснение; нельзя полагаться только на opacity.

## 7. Consent, local-first и provenance

- Выбор фото, scene declaration, crop, outline и повторная проверка выполняются локально, до любых сетевых запросов.
- Перед входом в crop/outline показывается короткое уведомление, а не отдельное согласие: «Изменения выполняются на устройстве и удаляются при отмене». Отдельное explicit consent требуется для любого долговременного сохранения и отдельно — для будущей server/AI processing.
- Отказ от consent не блокирует retake, cancel и delete и не переводит пользователя в demo автоматически.
- Исходник сохраняется неизменным только если это уже разрешено действующим storage consent; рабочие производные имеют тот же или более короткий lifecycle.
- Provenance производной: `source=local_user_crop` либо `source=local_manual_outline_crop`, ссылка на локальную попытку, версия алгоритма и timestamp. Не хранить identity/person descriptor.
- Personal результат не может использовать demo items, а demo не должен получать personal photo, crop или outline. Переход между режимами требует явного действия и не переносит asset.

## 8. Acceptance criteria

### Blocking functional

1. `person_present`, `person_unknown`, `multiple_garments` и `ambiguous` всегда дают blocked state; `upload_allowed=false`, `network_allowed=false`, `local_ready=false`.
2. Ни crop, ни подтверждённый outline не дают `accept`/`save_and_review` напрямую и не ослабляют single-garment gate.
3. После любой производной выполняется повторная scene declaration без предвыбранных ответов и существующий quality gate.
4. Crop использует только существующие пиксели; generative fill/inpainting/background removal отсутствуют.
5. Cancel/delete очищает исходник, preview, crop, outline и object URLs текущей несохранённой попытки; reload не восстанавливает их без storage consent.
6. На всех blocked/error ветках доступны retake и delete; пользователь не попадает в бесконечный цикл.
7. Ни UI, state, analytics, logs, fixtures, screenshot names, export, storage keys, ни payload не содержат identity, face embedding или выводы о теле/здоровье/возрасте/гендере/этничности.
8. До processing consent отсутствуют запросы с байтами фото или производными. Само согласие не разрешает upload, пока gate не дал допустимый статус.
9. Demo/personal negative tests доказывают отсутствие переноса asset и смешения provenance.

### Mobile and accessibility

10. Viewports 320, 360, 390, 412 и 430 px проходят P0–P7 в portrait; 667×320 и 844×390 — short landscape sanity.
11. Нет horizontal overflow; target size ≥44×44 px; safe-area и virtual keyboard не перекрывают причину, retake или delete.
12. Полный keyboard flow работает без pointer; focus не теряется после state swap, Back, retry и delete.
13. NVDA/Windows + VoiceOver/iOS + TalkBack/Android корректно объявляют причину, privacy distinction, состояние и CTA; ручной outline не объявляется полностью доступным, если визуальный предмет нельзя независимо определить.
14. 200% zoom/text spacing и 2× Russian copy сохраняют весь смысл; reduced motion не меняет доступность действий.
15. Негативная формулировка audit: нет стыда, обвинения, оценки внешности и утверждений личности. Все причины сформулированы как ограничения продукта или требования к кадру.

## 9. Evidence plan

Для снятия HOLD нужен единый build ID и обезличенный пакет:

- state-transition log по P0–P7 с `person_present`, `person_unknown`, multiple, safe crop, unsafe crop, outline, cancel/delete и local error;
- network trace, подтверждающий zero photo/derivative requests до отдельного consent и допустимого gate status;
- storage dump до/после cancel, delete и reload;
- screenshots на обязательных viewport для person, multiple, crop, outline, recheck, delete и long-copy/200%;
- keyboard focus log и ручные NVDA/VoiceOver/TalkBack transcripts;
- tests, что crop не добавляет пиксели за пределами original и не вызывает generative/background-removal path;
- telemetry allowlist audit и поиск запрещённых identity/body полей;
- demo/personal negative fixtures только с синтетическими изображениями одежды; реальные пользовательские фото не входят в evidence.

## 10. Риски и зависимости

| Приоритет | Риск / зависимость | Условие снятия |
|---|---|---|
| P0 | Crop может оставить часть человека или вторую вещь | Повторная декларация + fail-closed scene gate; unsafe crop ведёт только в retake |
| P0 | Контур ошибочно воспринимается как detector | Copy, state и tests запрещают прямой переход в review/accept |
| P0 | Удаление очищает не все локальные производные | Единый attempt ID, lifecycle inventory и reload/storage evidence |
| P0 | Identity/body inference проникает через будущую модель или telemetry | Полевая allowlist, provider review, negative contract tests; до этого integration HOLD |
| P0 | Gate ослабляется ради конверсии | Регрессия существующих single-garment/person tests является release blocker без исключений |
| P1 | Ручной outline недоступен незрячему пользователю | Равноправный retake path; отдельное исследование assistive selection до заявления parity |
| P1 | Mobile crop ломается с zoom, keyboard или orientation | Реализация без drag-only и evidence на обязательной матрице |
| P1 | Долгая copy воспринимается как обвинение | Content review с anti-shame checklist и usability test |
| P1 | Неясный consent смешивает local edit и network processing | Раздельные тексты/состояния; сетевое согласие никогда не подразумевается локальным действием |
| P1 | Demo/personal asset leakage | Scope validation на create/read/delete/export и negative reload tests |

Зависимости для реализации: versioned local crop contract; единый photo-attempt lifecycle и delete API; повторная scene declaration; доступные crop controls; state-level network assertion; content/a11y review; synthetic multi-garment/person-presence fixtures без biometric labels. Auth, Supabase, VK ID, payments и retail не являются зависимостями этой ветки и остаются вне scope.

## 11. PASS / HOLD

- **PASS — документ:** безопасная UX-ветка определена, текущий default не ослаблен, person presence отделён от identity, предусмотрены crop/retake/manual outline, anti-shame copy, mobile/a11y criteria, local-first consent/delete и demo/personal границы.
- **HOLD — пользовательский выпуск:** production runtime этой задачей не менялся; нет реализованного local crop flow, повторного gate, lifecycle/delete evidence и ручных mobile/SR прогонов.
- **GO возможно только если:** выполнены все blocking criteria 1–15, evidence относится к одной сборке, сетевые/identity/privacy утечки равны нулю, а существующий single-garment gate проходит регрессию без ослабления.
