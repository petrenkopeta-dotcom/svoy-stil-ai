# OUTFIT-09 — UX/UI-матрица личного образа

Статус: **PASS — UX-контракт готов; HOLD — реализация и device QA не входят в задачу**  
Дата: 21.08.2026  
Scope: mobile-first экран выбора одного образа только из подтверждённых вещей личного гардероба.

## 1. Решение и границы

Экран помогает ответить на один вопрос: **«Надела бы я этот образ сейчас?»** Пользователь видит цельный комплект, происхождение каждой вещи, короткое проверяемое объяснение и может заменить ровно одну вещь, не теряя остальные.

Жёсткие инварианты:

- `mode=personal` и единый `owner_scope`: все показанные и предложенные для замены вещи принадлежат текущему личному гардеробу;
- demo, retail, внешние изображения и «похожие товары» не попадают в экран, выдачу замены, сохранение или feedback;
- при смешанном, неизвестном или неподтверждённом происхождении результат не показывается как личный: состояние fail closed;
- экран не вызывает auth, Supabase, VK ID, оплату или внешние каталоги и не обещает их наличие;
- фото и метаданные читаются из локального personal storage; отсутствие фото не делает вещь недоступной;
- UI не показывает пользователю score, confidence, rank, проценты совместимости или скрытые оценки тела/внешности;
- объяснение содержит только подтверждённые allowlist-факты. Unknown остаётся unknown и отображается нейтрально;
- замена атомарна: одна выбранная вещь меняется на одну подтверждённую альтернативу, остальные `item_id` остаются неизменными;
- до подтверждения замены исходный образ остаётся текущим; ошибка или отмена ничего не изменяет;
- сохранение и явная реакция относятся к итоговой ревизии personal-образа, а не к промежуточному preview.

Не входит: генерация кандидатов, распознавание фото, облачная синхронизация, авторизация, коммерческие рекомендации, покупка, публичная оценка образа.

## 2. Информационная архитектура mobile-first

Порядок блоков на 320–430 px:

1. компактный header: назад, `ЛИЧНЫЙ ОБРАЗ`, меню дополнительных действий;
2. заголовок и подтверждённый контекст (`повод`, погода — только если задана);
3. визуальная матрица вещей;
4. индикатор позиции `Образ 1 из N`, только когда `N` реально известно;
5. краткое объяснение с раскрытием деталей;
6. явные действия изменения образа;
7. feedback;
8. sticky footer с одним primary CTA.

На ≥768 px визуал и пояснение образуют две колонки 58/42. Максимальная ширина контента — 1120 px; смысловой и DOM-порядок остаётся mobile-first. Sticky footer превращается в обычную панель действий в правой колонке.

Основной CTA по состоянию:

- новый образ: `Сохранить образ`;
- уже сохранён: `Сохранено` (не disabled-only: рядом доступно `Убрать из сохранённых` в меню);
- preview замены: `Заменить вещь`;
- ошибки/empty: контекстное восстановление, описанное ниже.

## 3. Визуальная матрица и карточка вещи

### 3.1 Матрица

- 2 колонки на 320–430 px, gap 12 px; одна широкая карточка допустима для единственной вещи, но неполный комплект не называется готовым образом.
- На ≥600 px — адаптивные 3–4 колонки. Карточки не переставляются только ради визуальной симметрии: порядок стабилен `верхний слой → верх/платье → низ → обувь → аксессуар`.
- Карточка целиком открывает детали, но отдельная кнопка замены имеет собственную hit area и имя.
- Изображение: `aspect-ratio: 4/5`, `object-fit: contain`, нейтральный локальный фон. Нельзя кропать часть вещи так, чтобы менялся её смысл.
- Если фото отсутствует/не читается, показывается локальный category placeholder и текст `Фото не добавлено`; название и категория остаются доступны.
- Якорная вещь имеет метку `Оставляем в образе`; её замена доступна только после явного снятия якоря.

### 3.2 Состав карточки

Обязательные поля:

- локальное фото или placeholder;
- подтверждённое пользовательское название, иначе безопасная категория (`Верх`, `Низ`, `Обувь`, `Вещь без категории`);
- основной цвет только если подтверждён; unknown не заменяется придуманным цветом;
- метка `Из моего гардероба`;
- кнопка `Заменить {доступное имя вещи}`.

Не показывать сырые taxonomy-коды, внутренние ID, rule IDs, цену, бренд или материал, если пользователь их не подтвердил. Длинное название занимает до трёх строк, затем карточка растёт; смысловой текст не обрезается многоточием.

Accessible name изображения не повторяет всю карточку: для информативного фото `Фото: {название}`, для placeholder изображение декоративное. Кнопка замены получает уникальное имя, например `Заменить: молочная рубашка`.

## 4. Объяснение

### 4.1 Короткий уровень

Заголовок: `Почему этот образ`.

Показываются максимум три подтверждённые причины в приоритетном порядке:

1. явный контекст/ограничение пользователя;
2. сочетание вещей (цвет, силуэт, слои);
3. подтверждённое личное предпочтение.

Формула строки: **подтверждённый факт → наблюдаемое решение**, без обещания результата. Пример: `Для долгой прогулки выбрана обувь с подтверждённым комфортом.`

Ссылка `Подробнее` раскрывает секции `Контекст`, `Цвета`, `Силуэт`, `Предпочтения`. Неподтверждённая секция не скрывается за уверенной формулировкой: `О балансе силуэта пока нет подтверждённых данных.`

### 4.2 Правила честности

- Причина с `confirmed=false`, неизвестным code или без evidence не рендерится как факт.
- Отсутствие погоды означает `Погода не указана`, а не «подходит по погоде».
- `all_season`, нейтральный placeholder или дефолтное числовое значение не используются в пользовательском объяснении как подтверждение.
- Нельзя писать `идеально`, `подходит вашей фигуре`, `омолаживает`, `стройнит`, `ваш цветотип`, `95% совместимости`.
- Если известных причин нет: `Пока недостаточно подтверждённых данных, чтобы честно объяснить этот образ.` CTA `Проверить данные вещей` ведёт в локальное редактирование и после возврата сохраняет выбранный образ.

## 5. Замена ровно одной вещи

### 5.1 Вход и bottom sheet

Нажатие `Заменить…` открывает modal bottom sheet на mobile и dialog на desktop:

- заголовок `Чем заменить {название}?`;
- reassurance `Остальные вещи останутся в образе`;
- текущая вещь закреплена сверху и помечена `Сейчас в образе`;
- альтернативы — только personal items того же `owner_scope`, прошедшие hard constraints;
- фильтр по категории применяется системой, но не выдаётся за доказательство сочетаемости;
- карточка альтернативы показывает только подтверждённые поля и действие `Посмотреть в образе`.

Sheet имеет visible close, закрывается Escape, держит focus trap и возвращает фокус в кнопку исходной карточки. Drag-to-dismiss может быть дополнением, но не единственным способом закрытия.

### 5.2 Preview и подтверждение

После выбора альтернативы sheet закрывается, в матрице меняется одна карточка и появляется review-banner:

`Предпросмотр: {старая вещь} → {новая вещь}. Остальные вещи не изменились.`

Действия:

- primary `Заменить вещь` — фиксирует новую ревизию;
- secondary `Отменить` — восстанавливает исходную ревизию;
- text action `Выбрать другую` — снова открывает список для того же слота.

Объяснение preview пересчитывается только по фактам новой комбинации. Пока оно загружается, старые причины не остаются под новой вещью: показывается skeleton/`Проверяю сочетание…`. Если объяснение недоступно, замена может быть подтверждена только как визуальный выбор с честной меткой `Объяснение пока недоступно`; система не придумывает причину.

После успеха: live-status `В образе теперь {новая вещь}. Остальные вещи сохранены.` Focus переходит на обновлённую карточку. Undo `Вернуть {старую вещь}` доступен в snackbar не менее 8 секунд и в истории текущей сессии.

### 5.3 Защитные условия

Операция отклоняется без изменения UI-state, если:

- альтернатива demo/retail/unknown или другого owner scope;
- исходная ревизия устарела;
- вещь удалена либо изменилась во время preview;
- замена нарушает явное ограничение;
- ответ содержит больше одного изменённого `item_id`.

Текст: `Не удалось безопасно заменить только эту вещь. Исходный образ сохранён.` Действия: `Повторить` и `Закрыть`.

| Unknown/mixed provenance | никакие карточки потенциально чужого происхождения не показываются | `Вернуться в гардероб` | `Повторить проверку` | alert: `Не удалось подтвердить, что все вещи из вашего гардероба.` |

| Local data unavailable | personal-контент не подменяется demo | `Вернуться в гардероб` | `Повторить` | `Личный гардероб сейчас недоступен на этом устройстве.` |
| Save error | образ остаётся на экране, saved-state не включается | `Повторить сохранение` | `Продолжить без сохранения` | `Не удалось сохранить образ. Сам гардероб не изменён.` |

## 7. Действия и feedback

Иерархия ready-state:

1. `Сохранить образ` — primary;
2. `Показать другой` — secondary, не меняет личный гардероб;
3. `Надела бы` / `Не подходит` — явная реакция после просмотра;
4. замена — локальное действие конкретной карточки.

Реакция не отправляется автоматически при сохранении, замене, закрытии или времени на экране. После `Не подходит` можно предложить bounded reasons (`Не мой стиль`, `Не подходит для планов`, `Неудобно`, `Хочу заменить вещь`, `Другое`) с `Пропустить`; ни одна причина не выбирается заранее. Undo реакции доступен. Demo-feedback не попадает в personal learning.

## 8. Визуальные и responsive-правила

- Использовать текущую спокойную палитру продукта: canvas `#F7F8F3`, surface `#FFFFFF`, sage surface `#E9F0E5`, ink `#1F2A22`, muted `#617064`, primary/focus `#405943`, danger только для ошибок.
- Mobile gutter 16 px; touch target ≥44×44 px; радиусы карточек 18–24 px.
- Sticky footer учитывает `env(safe-area-inset-bottom)` и не перекрывает последнюю карточку/feedback.
- Normal text contrast ≥4.5:1, controls/focus/essential graphics ≥3:1; focus ring ≥3 px и не обрезается.
- Без горизонтального overflow на 320/360/390/412/430 px и при 200% zoom.
- Анимации 160–240 ms, только opacity/transform; `prefers-reduced-motion` убирает сдвиги и shimmer.
- Skeleton повторяет геометрию, но не имитирует реальный контент. Loading не блокирует назад/закрытие.
- Текст не зависит от пола пользователя; названия вещей склоняются только если есть безопасная authored-форма.

## 9. Accessibility-контракт

- Экран — `main`, один H1; список вещей — `ul`/`li` либо эквивалентный `role=list` без интерактивной вложенности button-in-button.
- DOM и визуальный порядок совпадают. При responsive-перестроении CSS `order` не меняет смысловой порядок.
- Bottom sheet — `role=dialog`, `aria-modal=true`, имеет label/description, focus trap, Escape и return focus.
- Статусы загрузки/успеха — polite; ошибки, блокирующие происхождение или сохранение, — alert без повторяющейся озвучки.
- Selected alternative имеет не только цвет: текст `Выбрано` и `aria-checked=true` в radiogroup либо native radio.
- Все icon-only controls имеют русское accessible name; декоративные иконки скрыты от AT.
- После retry focus остаётся на инициировавшем control до результата; после ошибки переводится в alert только когда продолжение невозможно.
- Keyboard-only путь: открыть вещь → заменить → выбрать альтернативу → preview → подтвердить/отменить → undo.

## 10. Acceptance criteria

- [ ] Ready-state отображается только при `mode=personal`, едином подтверждённом `owner_scope` и personal provenance каждой вещи.
- [ ] Demo, retail и unknown items не появляются ни в образе, ни в замене, ни в personal save/feedback.
- [ ] Каждая карточка показывает происхождение и безопасный fallback для неизвестного фото/названия/цвета.
- [ ] Нет публичных score, confidence, процентов или оценок тела/внешности.
- [ ] Каждая утвердительная причина трассируется к подтверждённому allowlist-факту; unknown/unconfirmed дают нейтральный fallback.
- [ ] Замена меняет ровно один `item_id`; остальные IDs и якорь неизменны.
- [ ] До confirm исходная ревизия остаётся текущей; cancel/error возвращают её без побочных эффектов.
- [ ] Объяснение не остаётся stale после preview замены.
- [ ] No-alternative и insufficient не подмешивают demo и не ведут во внешний retail.
- [ ] Loading/empty/error/offline/save-error имеют отдельные тексты, CTA и доступную семантику.
- [ ] Full keyboard flow, dialog focus, return focus, live regions и undo проходят проверку.
- [ ] Hit areas ≥44 px; contrast, 200% zoom и overflow проходят на 320/360/390/412/430/768/1280 px.
- [ ] Фото и personal metadata не уходят в сеть в рамках этого экрана; network absence не запускает скрытый fallback.
- [ ] Реакция пользователя только явная, отменяемая и относится к подтверждённой ревизии образа.

## 11. Evidence, зависимости и риски

### Evidence в текущем дереве

- `docs/stylist-reasoning-contract-v1.md`: versioned entities, confirmed `ReasoningFact`, unknown-safe defaults и bounded `AlternativeAction.replace`.
- `docs/stylist-explanation.md` и `src/stylistExplanation.js`: allowlist renderer, neutral fallbacks, неизвестные коды не превращаются в утверждения, публичные проценты отсутствуют.
- `schemas/stylist-reasoning-v1.schema.json`: структурированная замена и связь с reason facts.
- `src/main.jsx`: существующие personal look, empty state, explanation и change actions; текущая реализация ещё не доказывает атомарную замену одной выбранной карточки.
- `src/honestReadiness.js`, `src/capsuleEngine.js` и тесты: fail-closed demo/personal и owner-scope boundary.

### Зависимости реализации

1. Контракт результата с `mode`, `owner_scope`, provenance каждой вещи и `outfit_revision`.
2. Replace API/локальный command с `base_revision`, `replace_item_id`, `replacement_item_id` и проверкой one-item diff.
3. Стабильные personal item IDs, категории и подтверждённые editable attributes.
4. Пересчёт ReasoningFact для preview без stale explanations.
5. Локальный persistence/undo для save, replace и feedback; без облачного предположения.
6. Реальные mobile/browser/a11y проверки, включая 200% zoom и screen reader.

### Риски и решение gate

| Риск | Severity | Mitigation / gate |
|---|---|---|
| demo/unknown попадает в личный образ | P0 | provenance + owner-scope validation до render/save/feedback; fail closed |
| замена незаметно меняет несколько вещей | P1 | revisioned one-item diff; reject whole operation при расхождении |
| объяснение остаётся от старого образа | P1 | очищать причины на preview и принимать только facts той же revision |
| placeholder трактуется как реальный факт | P1 | не включать defaults в evidence; явные unknown-тексты |
| sticky actions перекрывают контент на mobile | P2 | safe-area padding и матрица viewport/zoom |
| карточки перегружают экран и конкурируют с решением | P2 | progressive disclosure; один primary CTA; максимум три краткие причины |
| feedback становится скрытым обучением | P1 | только явное действие, undo, revision/origin binding |

**Итог:** `PASS` для передачи UX/UI-контракта в реализацию. `HOLD` для заявления о готовом пользовательском экране до реализации зависимостей, negative tests на provenance/one-item diff/stale revision и ручной mobile/a11y проверки.
