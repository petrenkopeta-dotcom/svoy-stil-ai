# PHOTO-PERSON-04 — пользовательское выделение вещи на фото человека

## Решение и статус

**Статус спецификации: PASS. Статус автоматического production-допуска: HOLD.**

PASS означает, что ниже определён проверяемый UX/геометрический контракт для ручной подсказки. HOLD означает, что один лишь контур не может перевести фото человека или неоднозначный кадр в автоматический `accept`, разрешить загрузку, распознавание либо обойти действующий single-garment gate. До отдельной реализации, тестов и privacy/security review функция остаётся изолированной локальной возможностью `guidance_only`.

Текущий путь «на фото одна отдельная вещь без человека» остаётся поведением по умолчанию. PHOTO-PERSON-04 — отдельный opt-in сценарий с явным согласием пользователя; он не меняет семантику существующих `declareGarmentOnly`, `save_and_review`, `retake`, `accept` и `upload_allowed`.

## Область и запреты

Сценарий позволяет человеку вручную указать видимую область **одной выбранной вещи** на локальном фото. Результат нужен только как подсказка для кадрирования/последующей пользовательской проверки.

Вне области: сетевые загрузки; облачное хранение; биометрия и идентификация лица; face/body embeddings и шаблоны; выводы о теле, здоровье, возрасте, гендере или этничности; генеративная дорисовка/inpainting; Auth, Supabase, VK ID, платежи, retail. Контур не является сегментацией модели, доказательством владения вещью или подтверждением её типа, цвета, посадки, размера и иных свойств.

## Пользовательский поток

1. До входа в редактор показать отдельное согласие: фото содержит человека; обработка контура локальная; сохранение/удаление управляется пользователем; контур — только подсказка. Отказ оставляет исходный single-garment путь без ухудшения.
2. Показать ориентированное изображение и инструкцию: «Выберите одну вещь и обведите только видимую внешнюю границу. Не дорисовывайте скрытые части».
3. Пользователь добавляет вершины указателем или клавиатурным способом, может отменять точки и начать заново.
4. Перед подтверждением интерфейс валидирует геометрию. Ошибка не исправляется автоматически и не создаёт сохранённый selection.
5. После подтверждения показать контур поверх того же ориентированного изображения и потребовать явную проверку: «Это та вещь?».
6. Результат получает `source: user_confirmed`, `purpose: guidance_only`, `garment_count: 1`; он не меняет decision/upload gate. Пользователь может изменить или удалить его.

## Контур, перекрытия и несколько вещей

### Устойчивый контур

- Полигон содержит минимум 3 различные конечные точки в нормализованном image space `[0,1] × [0,1]`.
- Вершины идут по порядку вдоль внешней видимой границы. Замыкание последней точки на первую выполняется интерфейсом, без дублирующей конечной вершины.
- Допустим вогнутый простой полигон. Недопустимы самопересечения, касание/наложение несоседних рёбер, повторные вершины, рёбра нулевой длины и почти вырожденные «иглы».
- Касание границы изображения допустимо (`0` и `1` включительно); выход за неё недопустим. Координаты указателя разрешено clamp-ить только для погрешности не более 0.5 CSS px после hit-test. Более дальнее попадание отклоняется как «вне изображения».
- Минимальная площадь — `0.001` площади ориентированного изображения. Дополнительно bounds должны иметь ненулевые ширину и высоту. Порог — защита от случайного клика, а не вывод о размере вещи.
- Для численной устойчивости проверки используют epsilon, определённый реализацией и зафиксированный тестами; округление для отображения не изменяет сохранённые координаты.

### Перекрытие (occlusion)

- Обводится только реально видимая область выбранной вещи. Нельзя соединять контуром раздельные видимые фрагменты через тело, другую одежду или объект так, будто скрытая часть известна.
- Один полигон v1 не представляет отверстия и несколько несвязных компонент. Если видимая область распалась на компоненты, пользователь выбирает одну достаточную компоненту либо получает честную рекомендацию переснять фото.
- Сильное перекрытие, при котором пользователь не может уверенно провести видимую границу, даёт `review/retake`, а не автоматическое восстановление силуэта.
- Никакой hidden-boundary completion, matte generation или inpainting не допускается.

### Несколько вещей в кадре

- Пользователь явно выбирает **одну** вещь до рисования; UI постоянно показывает её пользовательскую метку («выбранная вещь 1»), не классифицированную системой.
- Один selection не может охватывать несколько вещей. Если контур намеренно объединяет их либо выбор неоднозначен, подтверждение блокируется или результат остаётся `review_required`; автоматического разбиения нет.
- Добавление второй вещи требует нового независимого selection и отдельного подтверждения, но эта возможность не включается в production, пока отдельный multi-garment контракт не одобрен.
- Наличие нескольких вещей никогда не превращает PHOTO-PERSON-04 в обход текущего single-garment gate: default flow остаётся `retake/save_and_review` согласно существующей политике.

## Системы координат и преобразования

Канонические данные хранятся в координатах **ориентированных пикселей декодированного изображения**, после применения EXIF orientation и до CSS layout/crop:

```text
u = (clientX - renderedLeft) / renderedWidth
v = (clientY - renderedTop)  / renderedHeight
pixelX = u * orientedPixelWidth
pixelY = v * orientedPixelHeight
```

Обратное отображение: `clientX = renderedLeft + u × renderedWidth`, `clientY = renderedTop + v × renderedHeight`.

- `renderedLeft/Top/Width/Height` относятся к фактически нарисованному bitmap, а не ко всему контейнеру. Letterbox/pillarbox области при `object-fit: contain` не интерактивны.
- CSS border, padding, page scroll, devicePixelRatio, zoom и responsive resize учитываются через актуальный `getBoundingClientRect`; нельзя смешивать viewport `clientX/Y` с page `offset/pageX/Y`.
- При EXIF 2–8 сначала создаётся каноническое ориентированное изображение; natural width/height и все точки относятся к нему. Нельзя повторно применять EXIF к сохранённым точкам.
- Если UI использует crop, pan, zoom, CSS transform или `object-fit: cover`, pointer проходит через обратную матрицу display→oriented-image. Точки вне текущего видимого bitmap отклоняются. В v1 предпочтителен `contain` без пользовательского pan/zoom.
- Resize/rotation viewport не меняет normalized points; overlay пересчитывается из них. Смена самого blob, его orientation или crop revision инвалидирует selection и требует подтверждения заново.
- Сохранённый объект содержит `image_revision`/локальный непрослеживаемый идентификатор связи, размеры ориентированного bitmap и версию transform contract; запрещено использовать лицо, хэш биометрического шаблона или embedding как связь.

## Проверки геометрии

Подтверждение разрешено только когда одновременно выполнены условия:

1. все координаты конечны и находятся в `[0,1]`;
2. есть минимум 3 уникальные вершины и 3 уникальные позиции с учётом epsilon;
3. каждое ребро имеет длину больше epsilon;
4. signed shoelace area конечна, абсолютная площадь `>= 0.001`;
5. bounds конечны, лежат в `[0,1]`, имеют `width > epsilon`, `height > epsilon` и согласованы с вершинами;
6. ни одна пара несоседних рёбер не пересекается, не касается и не коллинеарно накладывается; для первого и последнего рёбер учитывается их соседство;
7. payload проходит schema/version validation и относится к текущей `image_revision`.

Порядок по/против часовой стрелки допустим и не несёт смысла. Bounds вычисляются из валидированных точек, не принимаются от клиента как доверенные. NaN, Infinity, строки, пропуски и чрезмерный объём точек отклоняются. Реализация должна ввести документированный верхний предел вершин (рекомендация v1: 256) для защиты UI от зависания.

## Undo и доступный fallback

- `Undo point` удаляет ровно последнюю добавленную вершину; повторяем до пустого состояния. `Ctrl+Z`/`Cmd+Z` делает то же, когда фокус внутри редактора и пользователь не редактирует текстовое поле.
- `Backspace/Delete` удаляет выбранную вершину только при явном фокусе вершины; клавиша никогда не вызывает навигацию страницы. `Escape` отменяет незавершённое перемещение, но не удаляет подтверждённый selection без диалога.
- `Start over` требует подтверждения, если есть подтверждённый или несохранённый контур; затем очищает точки и локальный draft. Должна быть отдельная команда `Delete selection` с понятным необратимым эффектом для текущего локального результата.
- Полный fallback без pointer: числовые X/Y в процентах или доступный список вершин с Add/Edit/Remove/Move up/Move down. Диапазон 0–100, ошибки сообщаются рядом с полем и через status/live region.
- Все команды доступны по Tab, имеют видимый focus, уникальные accessible names и touch target не менее 44×44 CSS px. Цвет не является единственным признаком ошибки/подтверждения.
- После undo фокус переходит на предыдущую вершину или кнопку Add; после ошибки — на сообщение/первое проблемное поле; после reset — на Add. Статус сообщает число точек и причину блокировки без утверждений о распознавании.

## Данные, согласие, удаление и разделение режимов

Минимальный локальный объект:

```json
{
  "version": "manual-outline-v1",
  "purpose": "guidance_only",
  "source": "user_confirmed",
  "image_revision": "local-opaque-revision",
  "oriented_width": 1200,
  "oriented_height": 1600,
  "garment_count": 1,
  "points": [{ "x": 0.1, "y": 0.2 }],
  "bounds": { "x": 0.1, "y": 0.2, "width": 0.4, "height": 0.5 }
}
```

Draft и подтверждённый контур остаются локальными и не попадают в analytics/logs. Сохранение между сессиями требует отдельного явного согласия; иначе данные живут только в памяти текущего сеанса. `Delete selection` удаляет draft, confirmed selection, preview/crop derivatives и локальную связь с изображением. Удаление исходного фото каскадно удаляет selection. UI сообщает завершение или честную ошибку удаления.

Demo-данные и personal-данные имеют разные namespaces/repositories и не копируются автоматически. Переход demo→personal требует отдельного выбора и согласия; очистка demo не затрагивает personal и наоборот. Ни один режим не разрешает сеть по умолчанию.

## Trust boundary

Доверенным считается только факт: пользователь подтвердил набор геометрически валидных координат для конкретной локальной ревизии изображения. Не доверяются и не выводятся: что внутри полигона действительно одежда; что это одна вещь; её категория/цвет/материал/размер; полнота видимой области; отсутствие человека; пригодность фото; личность или характеристики человека.

Любой downstream consumer обязан проверять `purpose === "guidance_only"`, версию, геометрию и `image_revision`, и может использовать selection лишь для preview/crop suggestion с финальной проверкой пользователем. Он не может выставлять `accept`, `upload_allowed`, `background_removal_allowed`, recognition confidence или ослаблять privacy/photo gates. Неизвестная версия и несоответствие ревизии fail closed.

## Acceptance criteria

- **AC-01 Default invariant:** без opt-in PHOTO-PERSON поведение single-garment gate побитово/семантически не меняется; фото человека не получает автоматический `accept`.
- **AC-02 Consent:** вход, сохранение и удаление имеют проверяемые явные состояния; отказ не создаёт selection.
- **AC-03 Transform:** тесты покрывают landscape/portrait, EXIF 1–8, letterbox/pillarbox, DPR 1/2/3, zoom и resize; одна и та же ориентированная пиксельная точка round-trip отображается с ошибкой не более 0.5 CSS px.
- **AC-04 Hit-test:** клики в padding/letterbox отклоняются; граничные точки bitmap принимаются без выхода за `[0,1]`.
- **AC-05 Geometry:** unit tests покрывают convex/concave PASS; NaN/Infinity/out-of-bounds/duplicates/zero edges/tiny area/collinear/self-cross/touch/overlap FAIL; bounds пересчитываются.
- **AC-06 Occlusion:** UX не предлагает дорисовать скрытую область; раздельные компоненты и сильное перекрытие приводят к выбору одной компоненты или retake/review.
- **AC-07 Multiple garments:** UI требует одну выбранную вещь; общий контур не даёт auto-accept; multi-selection выключен до отдельного допуска.
- **AC-08 Undo/a11y:** mouse, touch и keyboard-only сценарии позволяют создать, исправить, подтвердить и удалить контур; shortcut не перехватывается в полях ввода; focus/status проверены.
- **AC-09 Revision safety:** замена/поворот/crop revision изображения инвалидирует старый selection; stale/unknown payload fail closed.
- **AC-10 Trust boundary:** интеграционный тест доказывает, что подтверждение контура не меняет `upload_allowed`, recognition/accept и background-removal gates.
- **AC-11 Local-first:** сетевой spy фиксирует ноль запросов; selection отсутствует в telemetry/logs/storage без отдельного consent.
- **AC-12 Delete/separation:** удаление каскадно очищает локальные derivatives; demo/personal fixtures не читают и не удаляют данные друг друга.

## Риски и меры

| Риск | Мера | Остаточный статус |
|---|---|---|
| Пользователь воспринимает контур как распознавание | Постоянный текст `guidance_only`, финальная проверка, запрет confidence/accept | Средний; UX-тест до production |
| Ошибка EXIF/CSS transform смещает область на тело/лицо | Канонический oriented image space, inverse transform, round-trip матрица тестов | HOLD до evidence |
| Самопересечение/почти вырожденный контур ломает crop | Robust predicates с epsilon, area/bounds/edge limits, fail closed | HOLD до unit/fuzz evidence |
| Несколько вещей обходят single-garment gate | Одна вещь/selection, отдельное подтверждение, downstream invariant | Низкий после integration test |
| Occlusion провоцирует выдуманную границу | Только видимая область, component/retake guidance, без completion/inpainting | Средний, зависит от текста UX |
| Фото человека или контур утекает в сеть/telemetry | In-memory default, network spy, data minimization, explicit save/delete | HOLD до privacy test |
| Pointer-only UX исключает часть пользователей | Редактор списка/координат, undo/focus/live status, touch targets | HOLD до keyboard/screen-reader QA |
| Слишком много вершин создаёт DoS UI | Верхний предел, линейные/ограниченные проверки, отказ без зависания | Низкий после perf test |

## Evidence для снятия HOLD

Нужен единый локальный evidence bundle с commit SHA/dirty-tree disclosure и без пользовательских фотографий:

1. unit/fuzz отчёт geometry validator, включая касания и коллинеарные наложения;
2. transform fixtures EXIF 1–8 и скриншоты overlay для mobile/desktop/DPR;
3. browser-тесты pointer, touch emulation, keyboard-only, undo/reset/delete и focus management;
4. integration trace состояния photo gate до/после confirm, доказывающий неизменные `accept`/`upload_allowed`;
5. network/telemetry/storage spy с нулевыми утечками без consent;
6. тест каскадного удаления и изоляции demo/personal;
7. ручная проверка occlusion/multiple-garment copy на синтетических или явно разрешённых локальных fixtures.

До появления всех семи групп evidence итоговый production verdict остаётся **HOLD**.

## Зависимости

- существующий локальный intake/orientation pipeline и стабильный `image_revision` после EXIF normalization;
- отдельный pure geometry validator с robust segment intersection и фиксированным epsilon/vertex limit;
- доступный outline editor и keyboard vertex list;
- локальный consent/delete lifecycle и раздельные demo/personal repositories;
- неизменённый single-garment/photo gate как downstream policy authority;
- browser/unit/fuzz harness и разрешённые синтетические fixtures;
- privacy/security и accessibility review перед любым production enablement.
