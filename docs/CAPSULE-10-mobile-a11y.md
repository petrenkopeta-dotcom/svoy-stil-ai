# CAPSULE-10 — mobile/accessibility acceptance matrix

**Дата:** 2026-08-21  
**Объект:** будущий пользовательский контур капсул AI-стилиста  
**Решение:** **PASS — матрица готова как release gate; HOLD — выпуск капсул до получения capsule-specific runtime evidence.**

## 1. Границы решения

Этот документ проектирует проверку, но не утверждает, что UI капсул уже реализован или проверен. Текущий проект имеет общие browser-evidence для 320/360/390/412/430/1280, touch targets, клавиатуры, диалогов и reduced motion, однако переносить этот PASS на новый контур капсул нельзя.

В scope будущей проверки входят: список капсул, карточка капсулы, состав/образы, создание и редактирование, выбор только личных вещей, пустые/ошибочные состояния, длинные объяснения, ограничения тарифа и возврат в гардероб. Вне scope и остаются **HOLD**: production-авторизация, Supabase/облачная синхронизация, платежная реализация и VK ID. VK ID допускается только как исследовательский backlog.

Непереговорные продуктовые границы:

- demo и personal не смешиваются: демо всегда явно обозначено, личная капсула строится только из `source: "personal"`; demo-вещь нельзя незаметно сохранить или выдать за личную;
- локальный/personal режим честно сообщает, что данные находятся на этом устройстве; отсутствие auth/cloud не маскируется успешным сохранением;
- фото вещи, предпочтения и объяснения не требуют фото человека, параметров тела или вывода чувствительных характеристик;
- тарифные цены показываются ровно как **499 ₽** и **999 ₽**, без выдуманных entitlement-различий; пока серверный контракт прав не утверждён, CTA ведёт только к объяснению/листу ожидания, а не обещает покупку;
- paywall не возникает до первого реального результата; квота, дата сброса и отличие тарифов должны быть доступны до подтверждения действия;
- slow/offline не должен приводить к потере локально введённых данных или к ложному сообщению об облачном сохранении.

## 2. Статусы и обязательный тестовый набор

- **PASS:** критерий проверен на неизменной сборке и приложено воспроизводимое evidence.
- **FAIL:** воспроизводимое нарушение критерия; release-blocker до исправления и повторного полного прогона затронутой строки.
- **HOLD:** проверка невозможна из-за отсутствующего UX/контракта/окружения либо evidence отсутствует. HOLD не считается PASS.
- **N/A:** разрешён только с письменным обоснованием владельца продукта и accessibility QA; нельзя ставить для keyboard, screen reader, large text или offline целиком.

Обязательные viewport: **320, 360, 390, 412, 430 и 1280 CSS px**. Мобильная высота — минимум 844 px и дополнительный короткий viewport 568 px для 320; desktop — 1280×800. Проверить portrait на всех мобильных ширинах и landscape минимум на 320 и 430. Масштаб браузера 100%, затем text-only/OS large text по сценарию ниже.

Минимальные среды для release evidence:

- Chromium/Edge + Windows keyboard + NVDA;
- Safari iOS + VoiceOver на реальном устройстве хотя бы для 390 или ближайшего фактического viewport;
- Chrome Android + TalkBack на реальном устройстве хотя бы для 360 или 412;
- остальные ширины допускают автоматизированный Chromium-прогон, но он не заменяет два мобильных screen-reader smoke.

## 4. Blocking acceptance criteria

### B1 — layout и reflow

1. `document.documentElement.scrollWidth <= clientWidth` на каждой ширине, кроме заранее определённого горизонтального carousel с видимым названием и клавиатурной альтернативой; для капсул такой carousel по умолчанию не разрешён.
2. Ни один интерактивный элемент не выходит за viewport и не перекрывается sticky/fixed UI, экранной клавиатурой или safe-area inset.
3. Основной текст имеет комфортную меру на 1280 (ориентир 45–80 знаков), но критерий оценивается визуально, а не одним CSS-числом.
4. Поворот и возврат не сбрасывают форму, выбранные вещи и позицию пользователя.

### B2 — touch

1. Минимум 44×44 CSS px для кнопок, ссылок, checkbox/radio, меню карточки, удаления, назад и закрытия; расстояние исключает ошибочное соседнее нажатие.
2. Все действия доступны одним указателем без path gesture, hover или точного drag. Reorder: «Переместить выше/ниже» или эквивалент.
3. Скролл страницы не блокируется карточками; destructive action требует понятного подтверждения и допускает отмену.

### B3 — keyboard

1. Tab/Shift+Tab проходят все действия ровно один раз в визуально ожидаемом порядке; нет ловушки вне modal dialog.
2. Focus indicator контрастен, не обрезан и не скрыт sticky-элементом.
3. Диалог получает начальный фокус, удерживает его, закрывается Escape и возвращает фокус инициатору. После удаления фокус переходит к логичному соседу/заголовку списка.
4. Выбор вещей и изменение порядка полностью выполнимы клавиатурой.

### B4 — screen reader

1. У страницы один понятный `h1`; секции и карточки имеют программные названия. Повторяющиеся кнопки включают название вещи/капсулы.
2. Selected, expanded, disabled, current step, demo/personal, loading и error доступны программно, а не только цветом/иконкой.
3. Асинхронный результат объявляется коротким status-сообщением; подробный контент не перечитывается целиком. Ошибка — `alert` только при возникновении, без циклического повторения.
4. Декоративные изображения скрыты; содержательные называют вещь, не делают выводов о теле/человеке.
5. «499 рублей» и «999 рублей» вместе с периодом читаются без двусмысленности; зачёркнутые/старые цены не попадают в accessible name без необходимости.

### B5 — large text

1. При 200% zoom/text spacing (line-height 1.5, paragraph spacing 2, letter spacing 0.12em, word spacing 0.16em) весь контент и функции остаются доступны.
2. Нет фиксированной высоты для copy-контейнеров; текст не скрывается ellipsis там, где влияет на решение, privacy, provenance, тариф или ошибку.
3. Допустима одна ось прокрутки. Двухмерная прокрутка, наложение цены на CTA и исчезновение close/back — FAIL.

### B6 — reduced motion

1. Reduce применяется до первого meaningful paint: без стартовой вспышки полной анимации.
2. Отключены smooth scrolling, параллакс, автоматическое перелистывание, scale/slide и shimmer; допустим мгновенный fade/state swap.
3. Loading, успех и ошибка различимы текстом/иконкой и не зависят от движения.

### B7/B8 — slow и offline

1. Fixtures: Slow 3G; offline до открытия; offline после редактирования до save; обрыв после submit; восстановление сети; timeout/5xx; повторный reload.
2. Draft сохраняется локально либо до начала ввода явно предупреждается, что не сохранится. Retry не создаёт дубликат капсулы/вещей.
3. Offline-copy различает: «сохранено на устройстве», «ожидает отправки» и «не сохранено». Нельзя показывать «синхронизировано» без подтверждения.
4. Demo остаётся demo; offline fallback не подмешивает его в personal.

### B9 — long Russian copy

Использовать фиксированный набор, а не случайный lorem ipsum:

- название капсулы 120 знаков;
- название вещи 80 знаков и token 60 знаков без пробелов;
- объяснение стилиста 800 знаков с несколькими абзацами;
- privacy/offline error 350 знаков;
- тарифное описание 500 знаков, включая «499 ₽», «999 ₽», квоту и дату сброса;
- счётчики 1, 2, 5, 11, 21, 101 для русских форм;
- системный large-text и экранная клавиатура одновременно.

Copy может сворачиваться только с доступной кнопкой «Показать полностью», корректным `aria-expanded` и без сокрытия цены, provenance, ошибки, privacy или основного CTA.

### B10/B11 — provenance и privacy

1. Personal capsule принимает только подтверждённые personal IDs; demo/unknown/mixed payload блокируется до генерации и сохранения.
2. Маркер «Демо» не является только цветом и входит в accessible name/description. Переход к личному режиму требует явного действия.
3. Фото человека и параметры тела не запрашиваются. Фото вещи обрабатывается по существующему consent/privacy gate; cancel и delete реально прекращают/очищают работу.
4. Screenshot, trace, HAR, storage dump и SR transcript перед сохранением проходят redaction; реальные пользовательские фото и персональные данные не входят в QA fixtures.

### B12 — тарифы

1. Проверяются обе цены: 499 ₽ и 999 ₽, а также неизвестный/не загруженный entitlement.
2. UI не выводит различия тарифов из локальных счётчиков и не обещает лимит, период, cloud или функцию без утверждённого server-owned контракта.
3. До утверждения контракта допустим только нейтральный research/proposal экран; purchase CTA, успешная оплата и разблокировка — **HOLD**.
4. Тарифный экран не блокирует доступ к уже созданным локальным данным и privacy controls.

## 5. Критические journeys для каждого viewport

На каждой из шести ширин выполнить оба режима: pointer/touch и keyboard. Screen reader выполняется полностью на 390/ближайшем iOS, 360/412 Android и 1280 Windows; на остальных ширинах — автоматическая semantics-проверка плюс keyboard, без объявления её полноценной заменой ручному SR.

1. Открыть список без капсул → прочитать empty state → создать черновик → отменить → убедиться, что данных не добавилось.
2. Создать personal capsule из личных вещей → изменить порядок без drag → сохранить → открыть после reload → удалить с подтверждением и проверить focus/status.
3. Попытаться добавить demo-вещь в personal capsule → получить объяснимый блок без утечки/мутации → отдельно открыть явно обозначенную demo capsule.
4. Запустить long-copy + large-text → раскрыть объяснение → изменить вещь → убедиться, что CTA, provenance и privacy остаются видимыми/озвученными.
5. Начать создание на Slow 3G → нажать Save дважды → получить одну операцию → оборвать сеть → увидеть точный локальный/pending/failed статус → восстановить сеть → безопасно повторить.
6. Включить reduced motion до загрузки → пройти создание/удаление/диалог → убедиться в отсутствии motion-only feedback.
7. Открыть тарифное объяснение 499/999 ₽ после результата → прочитать цену/период/квоту → закрыть keyboard/SR → focus возвращается; без утверждённых entitlements покупка недоступна и честно объяснена.
8. Открыть privacy controls → экспорт/сброс/delete-all (на синтетических данных) → reload → нет удалённой капсулы, фото или draft.

## 6. Evidence и правило выпуска

Для каждого viewport сохранить обезличенные:

- JSON с viewport, DPR, browser/OS, input mode, motion/network/text settings, overflow, минимальной целью, ошибками console/page/request и результатом каждого B-критерия;
- screenshot normal, long-copy + large-text, offline/error и открытого dialog/drawer;
- keyboard focus-order log; для ручных SR-прогонов — краткий transcript с NVDA/VoiceOver/TalkBack и версиями;
- сетевой журнал с подтверждением отсутствия неожиданных внешних запросов и фото до consent;
- build identifier/hash и время запуска, чтобы evidence относилось к одной неизменной сборке.

Release rule: любая FAIL/HOLD в B1–B12 на любой обязательной ширине удерживает capsule release. Исключение возможно только через датированный risk acceptance владельцев Product, QA и Accessibility с узким scope и сроком устранения; demo/personal и privacy B10/B11 исключений не допускают.

## 8. Следующие задачи

1. **CAPSULE-P0-CONTRACT:** утвердить capsule state machine и schema (`draft/ready/saving/local_saved/pending/failed/deleted`, provenance, stable IDs), без auth/Supabase реализации.
2. **CAPSULE-P0-UX:** подготовить макеты 320/390/430/1280 для empty, edit, long-copy, mixed-source error, offline, delete и tariff education; приложить focus order и accessible names.
3. **CAPSULE-P0-TARIFF:** зафиксировать реальные различия 499/999 ₽, период, квоты, reset и server-owned entitlement semantics; до решения сохранить purchase HOLD.
4. **CAPSULE-P1-HARNESS:** расширить существующий mobile browser harness шестью ширинами, short viewport, overflow/touch/focus/long-copy/large-text/reduced-motion/slow/offline и provenance assertions.
5. **CAPSULE-P1-SR:** провести ручные NVDA + VoiceOver + TalkBack прогоны по journeys 1–8, сохранить обезличенные transcripts и дефекты.
6. **CAPSULE-P1-PRIVACY:** согласовать fixtures/evidence redaction и проверить отсутствие photo/network до consent, export/reset/delete/reload.
7. **CAPSULE-P1-RE-GATE:** после исправлений прогнать всю матрицу на одной сборке; опубликовать итог по каждой ячейке, не агрегируя HOLD/FAIL в общий PASS.
8. **BACKLOG-RESEARCH-VK-ID:** отдельно исследовать VK ID; не связывать с capsule release и не менять production auth.

## 9. Финальный PASS/HOLD

- **PASS:** документ задаёт конкретный, воспроизводимый acceptance gate и согласован с текущими границами mobile UX, privacy, local/demo/personal и ценами 499/999 ₽.
- **HOLD:** пользовательский выпуск капсул. Причины: нет утверждённого capsule UX/domain contract, capsule-specific runtime/SR evidence и зафиксированного entitlement-контракта тарифов.
- **Для снятия HOLD:** все B1–B12 должны иметь PASS на обязательных viewport и средах, P0-зависимости закрыты, evidence относится к одной сборке, а demo/personal и privacy негативные сценарии проходят без исключений.
