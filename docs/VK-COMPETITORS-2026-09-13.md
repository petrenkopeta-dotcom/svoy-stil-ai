# Конкуренты и адаптация для VK AI-стилиста

Дата проверки источников: **13 сентября 2026**. Первичный ограниченный обзор четырёх
реально существующих сервисов. Только официальные сайты, FAQ и карточка разработчика
в App Store. Регистраций, подписок, загрузки фотографий и firsthand-тестирования не было.
Ниже «заявлено» означает описание сервиса, а не проверенное качество, скорость или UX.
Отзывы пользователей, рекламные проценты и заявления об экономии не использованы как доказательства.

В частности, `id+sha256` фотографии недостаточно для цвета, категории, посадки и сезонности.
Нельзя при интеграции молча выставить confirmed=true всем модельным предположениям.

## Максимум три адаптации — приоритет и цена

Это **наши гипотезы**, а не измеренный uplift. Оценки S/M/L сравнительные, без обещания
срока/стоимости. Ноль новых платных API не означает нулевую стоимость хостинга: реальное
потребление всё равно должно пройти бюджетный admission с общим потолком5000руб, включая тесты.
Ни одна из идей не снимает release gate и не запускается до приёмки основного сценария.

| Приоритет | Предложение | Польза и проверяемая гипотеза | Трудоёмкость / бюджет / приватность |
| --- | --- | --- | --- |
| **1** | Довести первую подтверждённую вещь до первого образа из своего гардероба: показывать недостающие категории и собирать небольшой достаточный набор | Поэтапная оцифровка из Indyx + комбинации своей одежды в Whering/Stylebook. Проверять долю дошедших до первого пригодного личного образа и число лишних шагов; порог набора определяется движком, не рекламным обещанием «3 фото всегда достаточно» | **M/L**: связать VK identity/PNG/подтверждённые атрибуты с существующим composer; это отдельное согласование API. Без нового платного inference. Пока фото закрыты — только разрешённые ручные metadata, явные unknown и честное отсутствие полного образа |
| **2** | Краткое «почему» для личного образа + одна контролируемая замена с сохранением выбранной вещи | Использовать понятный паттерн редактируемых комбинаций; доказательное объяснение — наша адаптация, не заявленная копия конкурента. Проверять, понимает ли человек причину и ограничение, и может ли заменить одну вещь без потери остальных | **S/M** после№1: уже есть composer/anchor/explanation. Детерминированные правила, без генеративного текста и новых фото. Не выводить тип фигуры/посадку как факт без подтверждения |
| **3** | Добровольная отметка «носила сегодня» и простая история, затем предложение вновь использовать давно не отмеченную вещь | Общий паттерн календаря/частоты у Whering, Indyx, Stylebook. Проверять повторное полезное использование сервиса; «нет отметки» не равно «не носила». Не называть это доказанным ростом retention | **M**: новый тип события и owner-scoped хранение с отменой; не переименовать существующее would_wear. Только id вещи/образа и дата по явному действию; без selfie, геолокации, push и автоматического расписания. Cost-per-wear отложить до достоверных цены и носок |

Импорт чеков/магазинных аккаунтов, social sharing, обработка selfie и virtual try-on в эти
три предложения не входят: для текущего пути они добавляют внешние данные/приватностные
и инфраструктурные зависимости. Чужие тексты, дизайн и ассеты не копируются.

## Конкретный UX-выбор для визуализации до реализации

Вопрос для пользователя: **с чего начинать первый личный образ после demo/первой вещи?**
Это существенно разные маршруты, поэтому здесь не выбран победитель и код не менялся.
Координатору переданы три варианта для следующей визуализации на одинаковом сценарии:
пустой/малый гардероб, одна подтверждённая вещь, закрытые фото-gates.

| Вариант | Главный шаг пользователя | Плюс | Цена выбора |
| --- | --- | --- | --- |
| **A. От одной вещи** | Выбрать вещь, которую хочет надеть, затем добавить недостающие категории | Есть личная отправная точка; соответствует существующему anchor | Полный образ нельзя честно обещать после одной вещи; нужно ясно объяснить, чего не хватает |
| **B. Собрать минимальный набор** | Заполнить категории для одного базового комплекта, затем получить варианты | Прозрачный прогресс и определённый момент готовности | Больше ввода до результата; может ощущаться как анкета/каталогизация |
| **C. От ситуации** | Выбрать ситуацию, затем собрать достаточный набор своих вещей | Сразу понятна задача подбора; опирается на уже имеющиеся ответы onboarding | Риск повторно спрашивать уже известное; без вещей результат всё равно недоступен |

Следующий шаг — по согласованию координатора визуализировать эти маршруты для выбора
пользователем, а не реализовать один молча. До решения не создаются произвольные макеты.
Независимая security-проверка correctness-followup имеет приоритет над этими продуктовыми идеями.
